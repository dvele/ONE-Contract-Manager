# Dvele Contract Manager

A full-stack contract management platform built for modular home construction. Automates contract generation, manages child LLCs, handles state-specific legal disclosures, and provides a wizard-driven interface for creating MASTER_EF agreements.

## Getting Started

```bash
# 1. Clone the repository
git clone <repo-url>
cd dvele-contract-manager

# 2. Install dependencies
npm install

# 3. Set up environment variables
cp .env.example .env
# Edit .env with your database credentials (see Environment Variables below)

# 4. Push the database schema
npm run db:push

# 5. Seed initial data (clause library, variables, components, home models)
npx tsx scripts/seed_mvp.ts
npx tsx scripts/seed_variables.ts
npx tsx scripts/seed-components.ts

# 6. Start the development server
npm run dev
```

The app will be available at `http://localhost:5000`. Both the frontend (Vite dev server) and backend (Express API) are served on the same port.

## Environment Variables

Copy `.env.example` to `.env` and configure:

| Variable                    | Required | Default            | Description                                                   |
|-----------------------------|----------|--------------------|---------------------------------------------------------------|
| `DATABASE_URL`              | Yes      | -                  | PostgreSQL connection string (e.g., `postgresql://user:pass@localhost:5432/dvele`) |
| `NODE_ENV`                  | No       | `development`      | Environment mode. Set to `production` for production builds   |
| `PORT`                      | No       | `5000`             | Port the server listens on                                    |
| `SKIP_AUTH`                 | No       | `false`            | Set to `true` to bypass authentication (auto-skipped in dev)  |
| `ADMIN_SYNC_KEY`            | Yes (prod) | Weak default     | Security key for admin sync endpoints. **Must override in production** |
| `PUPPETEER_EXECUTABLE_PATH` | No       | Auto-detected      | Path to Chrome/Chromium binary for PDF generation             |
| `PROD_DATABASE_URL`         | No       | Same as DATABASE_URL | Production DB connection for sync scripts                   |

## Database Setup

The project uses **Drizzle ORM** with **PostgreSQL**. The schema is defined in `shared/schema.ts`.

```bash
# Push schema to database (creates/updates tables)
npm run db:push

# After schema changes, push again
npm run db:push
```

Migrations are stored in `migrations/` and generated by Drizzle Kit. The configuration is in `drizzle.config.ts`.

### Seeding Data

Run these scripts in order for a fresh database:

```bash
# Core MVP data (home models, sample project, clause library)
npx tsx scripts/seed_mvp.ts

# Variable definitions for contract template resolution
npx tsx scripts/seed_variables.ts

# Reusable contract components (signature blocks, tables)
npx tsx scripts/seed-components.ts

# Master EF contract template structure
npx tsx scripts/seed_master_ef_template.ts

# Ingest Master EF clauses from DOCX templates
npx tsx scripts/ingest_master_ef.ts
```

## Architecture Overview

### Data Flow

```
User (Browser)
    │
    ▼
React Frontend (Vite) ──── TanStack Query ────► Express API (/api/*)
    │                                                │
    ▼                                                ▼
Wizard UI (9 steps)                          Drizzle ORM / PostgreSQL
    │                                                │
    ▼                                                ▼
Contract Preview ◄──── Contract Generator ◄──── Variable Mapper
    │                        │                       │
    ▼                        ▼                       ▼
PDF / DOCX Download    Clause Assembly         Pricing Engine
                       Exhibit Resolution       Table Generators
                       XREF Cross-References    State Disclosures
```

### Key Design Patterns

- **Atomic Clause Architecture**: Clauses are stored as separate header + body units with hierarchical parent-child relationships. This enables flexible assembly, reordering, and contract-type filtering.

- **Dynamic Variable Resolution**: A unified mapper (`server/lib/mapper.ts`) serves as the single source of truth for all variable definitions. Variables like `{{COMPANY_NAME}}`, `{{CLIENT_LEGAL_NAME}}`, and `{{TOTAL_PROJECT_PRICE}}` are resolved at generation time.

- **Component Library**: Reusable contract blocks (signature tables, disclosure blocks, data tables) are stored in the `component_library` table and resolved via `{{BLOCK_*}}` and `{{TABLE_*}}` tags.

- **Multi-Contract Type Support**: The system supports `MASTER_EF`, `ONE`, `MANUFACTURING`, and `ONSITE` contract types, each with their own clause library, exhibits, and state disclosures.

- **Pricing Engine**: A 6-phase pricing system that accounts for design fees, offsite (factory) costs, logistics, onsite services, admin fees, and shipping. Prices are multiplied by unit quantity for multi-unit projects.

## Core Systems

### Contract Generation Wizard (9 Steps)

The wizard at `/generate-contracts` guides users through contract creation:

1. **Project Setup** - Project name, number, type, service model (CRC/CMOS)
2. **Client Information** - Buyer details, entity type, trust information
3. **Site Details** - Delivery address, site specifications
4. **LLC Selection** - Choose or create child LLC for the project
5. **Site & Home Selection** - Select home models, set quantities, configure units
6. **Pricing** - Review and adjust pricing (design fees, offsite, onsite, logistics)
7. **Payment Schedule** - Configure milestone-based payment terms
8. **Contractors** - Assign manufacturer and onsite contractors
9. **Review & Generate** - Final review, preview, and contract generation

### Variable Resolution System

The mapper (`server/lib/mapper.ts`) is the single source of truth for all contract variables. It resolves 200+ variables across these categories:

- **Project Variables**: `PROJECT_NAME`, `PROJECT_NUMBER`, `PROJECT_STATE`, etc.
- **Client Variables**: `CLIENT_LEGAL_NAME`, `CLIENT_ENTITY_TYPE`, `CLIENT_EMAIL`, etc.
- **LLC Variables**: `CHILD_LLC_LEGAL_NAME`, `CHILD_LLC_FORMATION_STATE`, etc.
- **Company Variables**: `COMPANY_NAME`, `COMPANY_SIGNATORY_NAME`, etc.
- **Financial Variables**: `TOTAL_PROJECT_PRICE`, `DESIGN_FEE`, `PRODUCTION_PRICE`, etc.
- **Table Variables**: `PRICING_BREAKDOWN_TABLE`, `PAYMENT_SCHEDULE_TABLE`, `SIGNATURE_BLOCK_TABLE`, etc.
- **Conditional Variables**: `IS_CRC`, `IS_CMOS`, `HAS_TRUST`, etc.

### Pricing Engine

Located at `server/services/pricingEngine.ts`, the pricing engine calculates:

- Design/pre-production fees
- Offsite (factory) base price per unit (multiplied by quantity)
- Logistics and shipping costs
- Onsite services (CMOS model only)
- Admin fees and reimbursables
- Total project price with unit quantity awareness

### Dynamic Cross-References (XREF)

XREF tags like `XREF_FEES_PAYMENT_SECTION` are resolved after clause numbering, providing accurate section references (e.g., "Section 4.2") throughout the generated contract.

### State Disclosure System

State-specific legal disclosures are managed in the `state_disclosures` table and resolved via `[STATE_DISCLOSURE:CODE]` tags within clause content based on the project's state.

### Responsibility Matrix

Configurable task allocation between Company and Client/GC for onsite work. Rendered dynamically in Exhibit C with defaults based on service model (CRC vs CMOS).

## Deployment

### Production Build

```bash
# Build the application
npm run build

# The output is in dist/ directory
# Start with:
NODE_ENV=production node dist/index.cjs
```

### Required for Production

1. PostgreSQL database with `DATABASE_URL` configured
2. Chrome/Chromium installed (or set `PUPPETEER_EXECUTABLE_PATH`) for PDF generation
3. `NODE_ENV=production` to enable authentication and production optimizations
4. Ensure `generated_contracts/` directory is writable

### Notes

- In development, authentication is automatically skipped
- The Vite dev server and Express API share the same port (5000)
- Generated contracts are stored in `generated_contracts/` directory
- PDF generation requires a headless Chrome instance via Puppeteer
